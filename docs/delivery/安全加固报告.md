# 安全加固报告（额度盗刷防护）

> 2026-08-24 | 触发背景：用户（大模型算力提供方）要求防止恶意套取 API token——攻击者脚本化调用患者端匿名接口逐轮消耗 MiMo（每会话约19次调用：9×understand + ≤10×tts），换 IP 即可无限盗刷。本轮安全审计另发现一处生产级高危漏洞。

## 一、审计发现（威胁模型）

| # | 威胁 | 原状 | 严重度 |
|---|------|------|--------|
| T1 | **生产部署下限流失效**（Nginx 反代后所有请求 IP=127.0.0.1，10/min 与登录锁定全部形同虚设）| 只读 request.client.host | 🔴高 |
| T2 | **无上游额度上限**：被盗刷时 MiMo 账单无封顶 | 无进程级预算 | 🔴高 |
| T3 | **打爆上游 RPM**：官方限 100/账号，直连无节流 → 429 链式失败甚至风控 | 无客户端限速 | 🔴高 |
| T4 | **静音/极短音频免检**：1 秒静音 WAV 即可过校验刷一轮 | 仅格式/时长>0，无能量检测 | 🟡中 |
| T5 | 单 IP 单窗口（10/min）窗口粒度粗，脚本可慢速渗透 | 仅分钟窗 | 🟡中 |
| T6 | 伪造头：X-Real-IP/X-Forwarded-For 未经信任直接可用会反向被利用 | 无防护，也未被使用 | 🟡中 |

## 二、加固措施（已实现，51/51 测试全绿）

1. **真实客户端 IP**（T1/T6）：`get_client_ip()` 仅当 `TRUST_PROXY=true`（生产 Nginx 后必须置 true）才信 X-Real-IP；否则一律用直连地址。患者在限流三池（分钟/小时/IP会话数）与登录锁定、医生端限流全部接入真实 IP。
2. **AI 调用硬预算**（T2）：进程级 24h 滑动窗口计数（understand/tts 全部入口），默认 20000 次/24h（可配 `AI_DAILY_CALL_BUDGET`）；超限统一 503 `AI_QUOTA_EXCEEDED`，80% 时 WARN 级告警留痕。**被盗刷的账单封顶 = 预算×单次成本**。
3. **上游 RPM 节流**（T3）：MiMoProvider 内置 60s 滑动窗口（默认 90 < 官方 100）+ 并发信号量 8；高峰期排队而非拒绝，保护账号不触发上游 429/风控。
4. **有效语音检测**（T4）：服务端对上传音频做 PCM 能量分析（RMS ≥0.004）与最短时长（≥0.5s）校验，纯静音/噪声包直接 400 `AUDIO_INVALID`——脚本需要合成"像人声"的音频才能刷，成本显著抬高（与前端 RMS 静默提醒形成前后端双保险）。
5. **小时级硬顶**（T5）：患者端新增 100/h/IP 第二窗口（`patient_limiter_hour`），与分钟窗叠加。
6. 上游调用 80% 预警日志（100/分钟与 20000/24h 双轨道）落 JSON 日志，便于告警接入（部署手册 §五监控基线）。

## 三、残余风险（记录在案）

| 项 | 说明 | 处置 |
|----|------|------|
| 能量检测可被"正弦波/白噪声+真波形组合"绕过 | 防刷门槛而非绝对防线 | 与预算封顶互补：绕过者仍需有效流量配额；审计日志可追溯 |
| 预算计数不落盘 | 重启归零 | 周界预算由 MiMo 控制台充值与 Key 额度兜底；后续可加落盘计数 |
| 分布式僵尸网络多 IP | IP 限流无法彻底防 | 预算硬顶是最终安全网；异常峰值告警人工介入 |
