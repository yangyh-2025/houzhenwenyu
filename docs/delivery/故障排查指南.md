# 故障排查指南

## 快速定位路径

```
现象 → systemctl status houzhenwenyu
     → journalctl -u houzhenwenyu -n 200（JSON 行日志，含 request_id/trace_id）
     → 按下表对症处理
```

| 现象 | 可能原因 | 处置 |
|------|---------|------|
| 服务起不来 | .env 缺失/DATABASE_URL 目录不可写 | 看 journalctl 启动段；确认 WorkingDirectory 可写 |
| /api/health 200 但页面白屏 | web/dist 未随包发布 | rsync web/dist 后无需重启（nginx 静态直出）|
| 患者端无法录音 | 非 HTTPS / 内核未就绪 / 权限拒绝 | 见 R4 真机清单；微信内核需联网自更新后重试；iOS 微信→引导 Safari（产品行为）|
| 大量 AI_PROVIDER_ERROR | MiMo 超时/限流(账号 RPM100)/欠费 | 控制台查余额与配额；AI_TIMEOUT_SECONDS 适当下调；错峰试点 |
| 登录一直"已锁定" | 连续5次失败触发 AUTH_LOCKED | 等10分钟或管理员线下重置（改库中 password_hash 或删行重启引导重建）|
| 医生看不到新记录 | 提交延迟≤30s 属正常 | 刷新列表；持续异常看 request_id 日志链 |
| 记录消失 | 到达 RETENTION_DAYS 被清理线程删除 | 清理留痕日志有 deleted=N 记录；属合规行为非故障 |
| 内存持续增长 | 会话只增不减 | 检查 SESSION_MAX_PER_IP/TOTAL 是否被调大过度；sweeper 每60s清理过期会话 |
| 端口占用 | 8000 被占 | PORT=8002 + nginx 同步改 upstream |

## 日志脱敏说明

应用日志不含音频/base64/摘要正文/就诊号全文（仅后四位）。排查涉及患者内容时，
以 trace_id 关联应用日志与访问日志即可定位请求，**不要**通过抓包方式取证患者音频。
