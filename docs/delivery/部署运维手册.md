# 部署运维手册

> 目标：空白 Ubuntu 22.04 / Debian 12 服务器，一条脚本完成标准化部署。

## 一、前置条件

| 项 | 要求 |
|----|------|
| 服务器 | 空白 Linux（Ubuntu 22.04+/Debian 12+），1C2G 起步 |
| 域名 | 已备案 HTTPS 域名 + TLS 证书（Nginx 层终结）|
| 产物 | 仓库代码（web/dist 已构建；或先在任意机器 `cd web && npm install && npm run build`）|
| AI Key | 小米 MiMo 控制台申请（platform.xiaomimimo.com，sk-xxxxx）；无 Key 可先 mock 上线演练 |

## 二、一键部署

```bash
# 在仓库根目录
bash deploy/deploy.sh
```
脚本动作：系统依赖 → /opt/houzhenwenyu 隔离目录 → venv 装依赖（清华镜像回退可用官方源）→ 生成 .env → systemd 托管自动重启 → nginx 站点 → 健康检查。
**部署后必做**：编辑 /opt/houzhenwenyu/.env——改 SECRET_KEY、DOCTOR_PASSWORD、AI_PROVIDER=mimo、AI_API_KEY，然后 `systemctl restart houzhenwenyu`。

## 三、日常运维

| 操作 | 命令 |
|------|------|
| 状态/日志 | systemctl status houzhenwenyu; journalctl -u houzhenwenyu -f |
| 重启 | systemctl restart houzhenwenyu |
| 手动备份 | deploy/backup.sh（VACUUM INTO 快照）|
| 定时备份 | crontab: `30 3 * * * /opt/houzhenwenyu/deploy/backup.sh` |
| 升级发版 | 新产物 rsync server/ 与 web/dist/ 后 restart；内存会话会丢活跃问诊（前端有中断引导闭环）|

## 四、安全清单（上线前逐项勾选）

- [ ] .env 中 SECRET_KEY 已换 ≥32 位随机值
- [ ] DOCTOR_PASSWORD 强密码且首次登录后评估更换策略
- [ ] AI_API_KEY 仅存于服务器 .env，未入 git
- [ ] HTTPS 生效（getUserMedia 硬要求）+ HSTS 头存在
- [ ] 未登录访问 /api/doctor/* 全部 401（curl 验证）
- [ ] RETENTION_DAYS 与院方合规确认一致
- [ ] 日志走 journald 自动轮转（勿另开文件日志）

## 五、监控与告警基线

- 存活：GET /api/health 应恒 200（nginx/systemd 双探针）
- 业务量：journalctl 统计 "POST /api/patient/consultations" 每日次数 ≈ 问诊量
- 异常信号：AI_PROVIDER_ERROR 频发=上游异常；AUTH_LOCKED 频发=疑似爆破
