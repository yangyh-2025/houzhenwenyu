## 三、隐私白名单与内存会话设计（核心取舍）

**PRD F9 留存白名单是硬约束：磁盘上只允许持久化四字段——就诊号、提交时间、对话轮次、摘要。**

- **活跃会话状态（含轮次文本历史）仅存内存**，绝不落盘。严格满足白名单。
- 完成时才写库四字段；中途退出或 TTL 过期（默认 30 分钟无活动）→ 非常静默丢弃。
- 音频字节仅在请求处理期间存在于内存，处理完即弃。
- 清扫线程每 60 秒扫描丢弃过期会话。
- 日志脱敏硬规则：不记音频字节/base64、摘要正文、就诊号全文（仅后四位）。

代价与接受理由：后端重启导致活跃会话丢失 → 前端收到 `CONSULT_SESSION_NOT_FOUND` 后大字引导重新扫码开始。低频事件，可接受（PRD 允许"重新扫码走一遍"）。

## 四、数据模型

唯一持久化表 consultations，五列：

| 列 | 类型 | 说明 |
|----|------|------|

## 五、API 规范

统一 envelope：成功返回业务 JSON；错误一律 HTTP 状态码 + `{"code","message","trace_id"}`，message 为适老化口语。

### 5.1 患者端

| 方法 | 路径 | 请求 → 响应 | 说明 |
|------|------|------------|------|
| POST | `/api/patient/consultations` | `{visit_number}` → `{session_id, rounds_limit, first_round:{text,audio_b64}}` | 创建会话，返回开场白包；限流 |
| POST | `/api/patient/consultations/{sid}/rounds` | `{audio_b64,duration_ms}` → 进行中:`{finished:false,round_index,text,audio_b64,rounds_remaining}` / 结束:`{finished:true,text,audio_b64,record_id}` | 提交一轮回答并推进对话；失败不计轮次（F3-R11）|
| POST | `/api/patient/consultations/{sid}/fixed-phrase-audio` | `{phrase_key}` 枚举白名单 → `{audio_b64}` | 固定话术语音（静默提醒/继续询问），杜绝自由文本 TTS 滥用 |
| GET | `/api/health` | → `{"status":"ok"}` | 存活检查 |

### 5.2 医生端（需登录 Cookie）

| 方法 | 路径 | 请求 → 响应 | 说明 |
|------|------|------------|------|
| POST | `/api/doctor/login` | `{username,password}` → 200+Set-Cookie；失败 401/423 | 连续5次锁10分钟 |
| POST | `/api/doctor/logout` | — → 204 | 删除服务端会话 |
| GET | `/api/doctor/me` | — → `{username}` | 登录态检查（前端路由守卫用）|
| GET | `/api/doctor/consultations?page=&page_size=&date_from=&date_to=&q=` | → `{items,total,page,page_size}` | 分页列表：就诊号/提交时间(epoch s)/轮次/摘要预览50字 |
| GET | `/api/doctor/consultations/{id}` | → 详情含九栏目 summary_text + disclaimer 字段 | 详情页数据源 |

### 5.3 错误码表（患者端 message 一律适老化口语）

| code | HTTP | 场景 |
|------|------|------|
| PATIENT_RATE_LIMITED | 429 | 请求过于频繁 |
| VISIT_NUMBER_INVALID | 400 | 号码格式非法 |
| CONSULT_SESSION_NOT_FOUND | 404 | 会话不存在/已过期/服务重启丢失 |
| AUDIO_INVALID | 400 | 音频校验失败 |
| AI_PROVIDER_ERROR | 502 | 上游AI接口异常（可重试）|
| AUTH_REQUIRED / AUTH_LOCKED | 401/423 | 未登录 / 账号锁定 |
| RECORD_NOT_FOUND | 404 | 记录不存在或已被清理 |

## 六、AI Provider 抽象与安全兜底

```python
class BaseProvider(ABC):
    async def understand(self, audio_b64: str, messages: list[dict]) -> str
    # 返回模型原始回复文本；由 consult service 解析【问诊结束】标记与摘要
    async def synthesize(self, text: text_type) -> bytes  # wav bytes
```

- MiMoProvider：按 R3 已证实 schema 实现（input_audio data URI / audio{format,voice}），httpx.AsyncClient，超时=配置项；
- ScriptedMockProvider：脚本化多轮问答+结束标记+九栏目摘要，无 Key 全功能开发测试演示；
- **安全兜底 safety.py**：模型输出经医疗建议黑名单正则过滤——问题轮命中→整条替换为中性追问固定话术；摘要轮命中行→删除该行。命中即 WARN 日志（不含正文）。红线不信任供应商自律。
- 轮次上限强制收尾：达10轮仍未收到结束标记 → 服务端追加一次无音频的纯文本总结调用生成摘要后收尾入库。
- 失败不计轮次实现：仅当 provider 调用成功返回后才把本轮 user 消息与回复写入会话历史并 rounds_used+=1；provider 异常向上抛 AI_PROVIDER_ERROR，客户端重试同一轮安全。

## 七·五 适老化前端工程红线（R4 W1-W6 全采纳）

- getUserMedia 必须在点击处理器同步栈内发起（W1）；录音启动800ms超时检测+明确失败话术（W4+）
- ScriptProcessor 主路径采集 PCM（W2）；前端编码 16kHz 单声道 WAV（W3）
- 患者端录入环节零 `<input>` 元素——自绘 div 键盘（W3+）
- TTS 元素级解锁：开始按钮点击栈内 play() 静音片段解锁该元素，ended 事件驱动状态机（W5）
- visibilitychange 中断恢复：返回前台重听当前问题重答（W5+）
- rem/clamp 布局适配微信关怀模式放大（W6）
- iOS+微信 UA 检测 → 常驻大字引导横幅（F5）；navigator.mediaDevices 缺失时同横幅兜底
